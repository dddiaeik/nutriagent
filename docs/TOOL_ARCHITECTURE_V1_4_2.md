# NutriAgent V1.4.2 도구 구조 실험

기준은 V1.4.1 커밋 `806ee6792d5733400e133af5dc59f0b5165bcb3c`다. 기본 실행 모드는 LEGACY이며 SPLIT은 실험용이다.

| 항목 | LEGACY | SPLIT |
| --- | --- | --- |
| 중량 유지 | `replace_food(old_food, new_food)` | `replace_food(old_food, new_food)` |
| 새 총중량 지정 | 같은 도구에 `quantity`, `unit` 전달 | `replace_food_with_weight(old_food, new_food, quantity, unit)` |
| 추가 질문 | `ask_clarification` | 기존 `ask_clarification` |
| 시스템 프롬프트 | V1.4.1 그대로 | 대체 지시 두 줄만 두 도구 선택 규칙으로 교체 |
| 실행 검증 | V1.4.1 검증 동작 | 새 양 근거 및 도구 선택 재검증, 일부 부정·상대·혼합 표현 차단 |

`NUTRIAGENT_TOOL_ARCHITECTURE=LEGACY` 또는 `SPLIT`으로 선택한다. 그 외 값은 명시적으로 거부한다. MOCK과 OLLAMA 모두 선택할 수 있다.

## 실행 검증

두 대체 경로는 `nutrition.replace_food`를 사용한다. SPLIT에서 숫자와 단위가 새 음식에 결합돼 있으면 그 총중량을 적용한다. 새 양이 없으면 명시적 중량 인수를 지우고 기존 행별 중량을 유지한다. 대체 요청에서 두 대체 도구의 선택을 정정할 수 있으며, 섭취 계산과 같이 의미가 다른 도구는 차단하고 질문한다. 기준 식단이 없거나 상대량, 범위 또는 불확실한 여러 수치가 있으면 추가 질문한다. 단일 수치를 거부하면서 기존 중량 유지를 명시한 표현에서는 기존 중량을 유지한다.

이 검증은 처리 가능한 문장 형태에 한정된다. 복합 식단 수정, 상대량 환산, 임의의 한국어·영어 문장 해석은 추가하지 않았다. V1.4.1 파서는 비교 기준으로 유지하므로 새로운 부정 표현 검증은 SPLIT에만 적용된다.

`raw_calls`는 모델이 생성한 모든 호출을 그대로 보존한다. 실행 시도와 보정은 `executed_calls` 및 `corrections`에 따로 기록한다. 원본 정확도의 차이는 스키마와 그 선택 지시를 함께 바꾼 결과로 해석한다. 최종 실행 차이에는 SPLIT의 새 검증도 포함된다. 예를 들어 거부한 중량을 명시한 경우, 원본 호출을 고정한 오프라인 재현에서 LEGACY와 SPLIT의 실행 결과가 달랐다. 이 차이는 모델의 도구 선택률을 측정한 결과와 별개다.

## 입력 크기

UTF-8 시스템 본문은 직전 식단을 붙이기 전, 도구 크기는 Ollama SDK가 직렬화하는 스키마를 압축 JSON으로 비교한 값이다.

| | LEGACY | SPLIT |
| --- | ---: | ---: |
| 시스템 본문 | 1,220 B | 1,162 B |
| 도구 스키마 | 2,571 B | 2,609 B |
| 합계 | 3,791 B | 3,771 B |

기존 프롬프트와 스키마의 SHA-256은 회귀 테스트에 고정했다. 실제 토큰 수와 Agent 응답 시간은 실추론 결과에서 산출한다.
